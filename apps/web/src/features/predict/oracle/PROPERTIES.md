# Predict flow: money properties

The oracle for every change to the predict flow. Tests and reviewers check code against this file, `allowlist.ts` and `tolerances.ts`; changing any of them needs Harman's approval.

| #   | Property                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Checked by                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| P1  | **Cap.** Every swap leg carries Algebra `limitSqrtPrice` at the target: UP buys and UP sells at the UP target, DOWN legs at `1 - target`. After a run, each traded pool's price is not past its target by more than `PRICE_TOLERANCE_TICKS`, including when the pool has a concentrated position between the price and the target, and when another account trades between quote and execution.                                                                                                                                                                                                        | calldata decode; fork tests                     |
| P2  | **Amounts.** The collateral split at the parent equals the funding breakdown the popup showed: exactly for sDAI; for xDAI, the minted sDAI plus the trade-wallet share, within `DUST_WEI`. Credits are spent exactly as shown: the transfer moves the wallet's credits shown and the spend burns the credits shown, each cut to the shown decimals; their swap's floor is split from xDAI at the parent and mints `previewDeposit` of it, within `DUST_WEI`. Leftover underlying in the trade wallet is reused, as the breakdown says; the credits swap's surplus over its floor stays there as WXDAI. | unit and fork tests                             |
| P3  | **One deposit, one credits transfer.** A run signs at most one collateral deposit, of the amount the popup showed, and at most one credits transfer to its trade wallet, of the credits shown. An xDAI deposit leaves at least `GAS_RESERVE_WEI` in the owner's wallet.                                                                                                                                                                                                                                                                                                                                | unit tests, calldata decode                     |
| P4  | **Owner.** Every transaction is sent from the run's owner. Every recipient (collateral `transfer`, `depositXDAI` argument, swap `recipient`) is the owner's own trade wallet. Recovery refuses when the connected account is not the run's owner.                                                                                                                                                                                                                                                                                                                                                      | calldata decode; driver tests                   |
| P5  | **Calldata matches the allow-list.** Every top-level and inner call is in `allowlist.ts` for the chain. Approvals equal the input of the call that follows them, are never unbounded, and are reset to zero after a swap that the limit stopped partway. No `delegatecall`; no native value inside `batchExecute`. A credits run's first batch is a `batchValueExecute` whose only native value is the parent `splitFromBase`, equal to the WXDAI unwrapped just before it; the credits manager spends its own collateral, so the trade wallet approves nothing for that swap.                         | `flow/allowed.ts`, at runtime and in unit tests |
| P6  | **Reviewed intent.** A run signs only the amount, token and estimates the popup showed when Predict, or Resume in recovery mode, was pressed.                                                                                                                                                                                                                                                                                                                                                                                                                                                          | driver tests                                    |
| P7  | **No double spend.** Across retry, resume and recovery, the parent split, the deposit, the credits transfer and the credits spend each happen at most once per run.                                                                                                                                                                                                                                                                                                                                                                                                                                    | driver and fork tests                           |
| P8  | **No floats on amounts.** No `number`, `parseFloat` or `Math.*` on an amount, price or balance path; amounts are `bigint`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | lint, review                                    |
| P9  | **Lens answers are checked.** A Lens answer is signed only when its router is the chain's Swapr router, its recipient the owner's trade wallet, its tokens and amount in those asked for, and its native value zero. The minimum out and the deadline are set by the app, not taken from the answer; the deadline is at most `QUOTE_DEADLINE_SECONDS` ahead.                                                                                                                                                                                                                                           | lens unit tests                                 |
| P10 | **Held quotes.** Confirm at Prices moved holds the run to the quotes it showed. Each leg's signed minimum is at least the output shown, scaled to what the leg spends, less the trade slippage.                                                                                                                                                                                                                                                                                                                                                                                                        | plan, lens and driver tests                     |
| P11 | **Held sends.** Every send is stored with the run (owner, nonce, block, transaction) before the wallet opens, and held until its hash is stored or its nonce shows how it ended. While a send is held or pending, its step is not signed again and the run is not reset or discarded.                                                                                                                                                                                                                                                                                                                  | driver tests                                    |
| P12 | **Session close.** No run starts, resumes, retries or confirms in the popup once the page reads the session as closed: its resolution date has passed and none of its pools holds liquidity. A session whose pools hold liquidity trades past the date.                                                                                                                                                                                                                                                                                                                                                | PredictRunner tests                             |
| P13 | **Credits floor.** The credits swap's floor is `max(quote, credits × CREDITS_MIN_RATE_WAD) × (1 − creditsBps)`, in WXDAI. A quote under that floor is refused before anything is signed.                                                                                                                                                                                                                                                                                                                                                                                                               | unit tests                                      |
| P14 | **Allow-list at runtime.** Before the wallet opens, each transaction is decoded against P4 and P5 with the connected account as sender. A departure stops the run as `unlisted`, with no prompt and no held send.                                                                                                                                                                                                                                                                                                                                                                                      | driver tests                                    |
| P15 | **Trade wallet by CREATE2.** The trade wallet is derived in the app from the factory, its salt and `TradeExecutor`'s creation code. A node that names another for the owner is refused, and nothing is paid to it.                                                                                                                                                                                                                                                                                                                                                                                     | unit tests                                      |
