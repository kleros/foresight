# Predict flow: money properties

The oracle for every change to the predict flow. Tests and reviewers check code against this file, `allowlist.ts` and `tolerances.ts`; changing any of them needs Harman's approval.

| #   | Property                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Checked by                             |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------- |
| P1  | **Cap.** Every swap leg carries Algebra `limitSqrtPrice` at the target: UP buys and UP sells at the UP target, DOWN legs at `1 - target`. After a run, each traded pool's price is not past its target by more than `PRICE_TOLERANCE_TICKS`, including when the pool has a concentrated position between the price and the target, and when another account trades between quote and execution.                                                                                                                                                                                                        | calldata decode; fork tests            |
| P2  | **Amounts.** The collateral split at the parent equals the funding breakdown the popup showed: exactly for sDAI; for xDAI, the minted sDAI plus the trade-wallet share, within `DUST_WEI`. Credits are spent exactly as shown: the transfer moves the wallet's credits shown and the spend burns the credits shown, each cut to the shown decimals; their swap's floor is split from xDAI at the parent and mints `previewDeposit` of it, within `DUST_WEI`. Leftover underlying in the trade wallet is reused, as the breakdown says; the credits swap's surplus over its floor stays there as WXDAI. | unit and fork tests                    |
| P3  | **One deposit, one credits transfer.** A run signs at most one collateral deposit, of the amount the popup showed, and at most one credits transfer to its trade wallet, of the credits shown. An xDAI deposit leaves at least `GAS_RESERVE_WEI` in the owner's wallet.                                                                                                                                                                                                                                                                                                                                | unit tests, calldata decode            |
| P4  | **Owner.** Every transaction is sent from the run's owner. Every recipient (collateral `transfer`, `depositXDAI` argument, swap `recipient`) is the owner's own trade wallet. Recovery refuses when the connected account is not the run's owner.                                                                                                                                                                                                                                                                                                                                                      | calldata decode; driver tests          |
| P5  | **Calldata matches the allow-list.** Every top-level and inner call is in `allowlist.ts` for the chain. Approvals equal the input of the call that follows them, are never unbounded, and are reset to zero after a swap that the limit stopped partway. No `delegatecall`; no native value inside `batchExecute`. A credits run's first batch is a `batchValueExecute` whose only native value is the parent `splitFromBase`, equal to the WXDAI unwrapped just before it; the credits manager spends its own collateral, so the trade wallet approves nothing for that swap.                         | calldata decode against `allowlist.ts` |
| P6  | **Reviewed intent.** A run signs only the amount, token and estimates the popup showed when Predict, or Resume in recovery mode, was pressed.                                                                                                                                                                                                                                                                                                                                                                                                                                                          | driver tests                           |
| P7  | **No double spend.** Across retry, resume and recovery, the parent split, the deposit, the credits transfer and the credits spend each happen at most once per run.                                                                                                                                                                                                                                                                                                                                                                                                                                    | driver and fork tests                  |
| P8  | **No floats on amounts.** No `number`, `parseFloat` or `Math.*` on an amount, price or balance path; amounts are `bigint`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | lint, review                           |
