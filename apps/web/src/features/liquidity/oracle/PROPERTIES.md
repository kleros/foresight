# Liquidity flow: money properties

The oracle for every change to the liquidity flow (seed, add, remove, merge). Tests and reviewers check code against this file, `allowlist.ts` and `tolerances.ts`; changing any of them needs Harman's approval.

| #   | Property                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Checked by                                                           |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| L1  | **Amounts.** The parent split is `max(A_O)` over branches. Each branch splits `s_O = ⌊A_O / 2⌋` of `O` into its children. Each pool's mint amounts come from Algebra's liquidity math at the exact `sqrtPriceX96` the mint will meet (the one passed to `createAndInitializePoolIfNecessary` for a new pool, `globalState().price` for an existing one): `L = min(L_for_amount0, L_for_amount1)`, shown amounts rounded up. Every token a run leaves in the wallet (unused `O`, the parent's and each child's INVALID, rounding under `DUST_WEI`) is shown in the popup before signing.                                                                                                                                                                                                                                | unit and property tests (`fc.bigInt`), fork tests                    |
| L2  | **Held price.** Every `mint` carries non-zero `amount0Min` and `amount1Min`: the shown amounts less `LIQUIDITY_SLIPPAGE_BPS` for an existing pool with liquidity, less `SEED_PRICE_TOLERANCE_TICKS` worth for a pool the run initializes or realigns. A branch's UP and DOWN prices sum to exactly 1 (`p_DOWN = 1 − p_UP`, in basis points), and each lies in `[MIN_SEED_PRICE_BPS, MAX_SEED_PRICE_BPS]`.                                                                                                                                                                                                                                                                                                                                                                                                              | calldata decode, fork tests (fills within tolerance, reverts beyond) |
| L3  | **Price lock only with liquidity.** A pool's price is locked to the pool's own only when its `liquidity() > 0`. A pool that is initialized but empty takes the user's price by a self-realign, in this order: mint a full-range position of `REALIGN_DUST_WEI` scale at the pool's current price; `exactInputSingle` against it with `limitSqrtPrice` at the target and `amountIn` capped at the exact input that dust position needs to reach the target plus `LIQUIDITY_SLIPPAGE_BPS`; withdraw and collect the dust position in full (and burn it); then mint the seed with L2's minimums. The owner ends with the dust tokens back less rounding under `DUST_WEI` per token. If the pool gained other liquidity before the swap, the cap bounds what the swap can spend and the seed mint reverts on its minimums. | unit tests, adversarial fork test                                    |
| L4  | **Owner.** Every transaction is sent from the connected account that reviewed the run. Every `mint` and `collect` recipient is that account and never the zero address. A position is only withdrawn when `ownerOf(tokenId)` is that account.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | calldata decode, driver tests                                        |
| L5  | **Calldata matches the allow-list.** Every call is in `allowlist.ts` for the chain. Approvals name only the Seer router, the position manager, or (for an L3 realign swap) the Swapr router, equal the amount the next call pulls, and are never unbounded. Token addresses come from `wrappedOutcome(i)` of the session's own markets and pools from `factory.poolByPair`, never from the indexer. A `multicall` wraps only the listed inner calls; a create and its mint name the same `token0`/`token1`, and that pair is one of this session's (parent outcome, child outcome) pairs. Splits and merges name sDAI as collateral and a market of this session. Native value only on `splitFromBase`. No `delegatecall`.                                                                                             | `flow/allowed.ts`, at runtime and in unit tests                      |
| L6  | **Remove and merge.** Remove withdraws every position the wallet holds in one pool, in one `multicall`: each one's full liquidity with its own non-zero minimums from the current price less `LIQUIDITY_SLIPPAGE_BPS`, then everything owed (`uint128` max) collected to the owner, then the emptied position burned. It names only that pool's positions, each once. Merge takes complete sets only, `min(UP, DOWN, INVALID)` at a branch and every parent outcome including INVALID at the parent, and returns exactly the amount shown.                                                                                                                                                                                                                                                                             | unit and fork tests                                                  |
| L7  | **Deadline and close.** Each mint, withdrawal and realignment deadline is the chain's time at build plus `LIQUIDITY_DEADLINE_SECONDS`. No add or seed once the chain's clock reaches the session's close; remove and merge stay allowed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | driver tests                                                         |
| L8  | **No double spend.** Across retry, resume and recovery, the parent split, each branch split, each mint and each withdrawal happens at most once per run. Every send is stored with the run before the wallet opens.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | driver and fork tests                                                |
| L9  | **Atomic path.** The run is sent as one EIP-5792 `wallet_sendCalls` only when the wallet reports `atomic` as `supported` or `ready` for the chain, always with `atomicRequired: true`, and its calls are byte for byte those the sequential path would send. Its `callsId` is stored before the wallet opens; a run whose batch status is unknown is not sent again.                                                                                                                                                                                                                                                                                                                                                                                                                                                   | driver tests                                                         |
| L10 | **Reviewed intent.** A run signs only the amounts, prices and pools the popup showed when Add, Remove or Merge was pressed. A changed pool state between review and build stops the run for a new review rather than signing different amounts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | driver tests                                                         |
| L11 | **No floats on amounts.** No `number`, `parseFloat` or `Math.*` on an amount, price or balance path; amounts and prices are `bigint`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | lint, review                                                         |
| L12 | **xDAI.** An xDAI split mints sDAI shares worth less than the xDAI sent; branch depths are capped at `previewDeposit(T) × (1 − MINT_RATE_MARGIN_BPS)`, and the split leaves `GAS_RESERVE_WEI` in the wallet.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | unit and fork tests                                                  |
| L13 | **Runtime decode.** Before the wallet opens, each transaction (each call of a batch) is decoded against L4 and L5 with the connected account as sender. A departure stops the run as `unlisted`, with no prompt and no stored send.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | driver tests                                                         |
